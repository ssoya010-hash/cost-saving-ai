What we found

Popular compressors (rtk 86K★, headroom 79K★, caveman 119K★) cut tokens per payload by 60–99%. In our 54-session re-test with their latest versions, none lowered the billed cost (−5% to +63%).

What works

Changing what the agent does: fewer turns, smaller and stable context, no cache rebuilds, less code. TokenEconomizer, Ponytail rule, codegraph on big repos.

Why it matters · the quarterly cap

Each of us has a quarterly AI budget. Every dollar saved per task is more work done.

Today usage is capped per quarter, roughly $200–1,000 per person depending on role. When the cap runs out, AI work stops until next quarter.

So the goal is not “spend less”. It is more completed tasks per dollar, so the same cap goes further.

−17% cost per task = +20% more AI work in the same quarter.
Illustrative: cap and cost per task vary by person. Tasks = cap ÷ cost per task; savings from slide 19.3
[왜 하는가] 지금 AI 사용은 분기별 한도가 있고, 사람마다 대략 200~1000달러 수준입니다. 한도를 다 쓰면 다음 분기까지 AI 작업이 멈춥니다. 그래서 목표는 덜 쓰는 것이 아니라 같은 돈으로 더 많이 끝내는 것입니다. 작업당 비용을 17% 줄이면 같은 한도로 20% 더 많은 작업을 할 수 있습니다. 그래프 숫자는 예시입니다.

Tool catalog · GitHub, stars, pros & cons

Tools that change what the agent does (and one that did not)

TokenEconomizer ★ 5.6K · plugin

pilot first
github.com/microsoft/TokenEconomizer

What: Controller that learns repo facts, prunes unused tools, stops failure loops.

PROS
  • −18 to −31% billed cost, 579 tasks
  • Pass@1 up in 4 of 5 setups
  • No proxy, no telemetry
CONS
  • Authors’ own paper, 1 month old
  • First ~5 tasks per repo cost more
  • Not usable in Devin cloud

Ponytail ★ 188K · skill

use as rule
github.com/DietrichGebert/ponytail

What: “Laziest senior dev”: smallest change, reuse, no speculative code.

PROS
  • −10.3% cost, p=0.004 (JetBrains)
  • Works anywhere as a text rule
  • Pass rate held
CONS
  • More missed tests/docs (27 vs 17)
  • Ours n=1: +29 / +6 / −6%
  • Trojan clone on a marketplace

codegraph ★ 77K · MCP

large repos
github.com/colbymchenry/codegraph

What: Pre-built code graph; one query instead of grep → read → read.

PROS
  • −16% cost on large repos
  • File reads −76%
  • Works in Devin via MCP
CONS
  • Ours +5 / +28 / +7% on a small repo
  • Agents often bypass it
  • Telemetry on; auto-allow perms

serena ★ 31K · MCP

avoid for cost
github.com/oraios/serena

What: LSP-based symbol search and editing tools.

PROS
  • Precise symbol-level navigation
  • Many languages via LSP
  • Liked by power users
CONS
  • Raised pooled cost (MS paper)
  • ~24K tokens of tool schema
  • Past critical RCE (patched)

First principles · what the bill is made of

72% of the bill is writing new context into the cache. Old context is already 90% off.

ATOM 1

Calls (turns × tool calls)

Each call re-sends the whole context. Fewer turns and loops cut everything.

ATOM 2

New context

Every new file, log or tool result is written to cache once at 1.25–2×.

ATOM 3

Cache rebuilds

A lost prefix is re-written in full. $66 of $185 on one Mac in one week.

ATOM 4

Output

Reasoning + code at 5×. Prose is a small part; less code is the lever.

Five whys, root cause: tools optimise tokens per payload; the bill is driven by calls × new context, rebuilds and output.
Claude pricing: write 1.25× (5 min) / 2× (1 h), read 0.1×, output 5× input. Devin CLI: 0.4 ACU per 1M input tokens, also cached.10
[1원리] 청구액을 쪼개 보면 72%가 캐시에 새 컨텍스트를 쓰는 비용입니다. 이미 캐시된 옛 컨텍스트는 0.1배라 거의 공짜입니다. 그래서 청구액을 움직이는 원자는 네 가지입니다: 호출 수, 새로 읽는 컨텍스트, 캐시 재작성, 출력. 특히 캐시 재작성은 제 Mac에서만 한 주에 185달러 중 66달러였습니다. 5 Whys로 내려가면 근본 원인은, 도구는 응답당 토큰을 줄이는데 청구액은 행동이 결정한다는 것입니다.

Architecture · why a tool works in one and not the other

Where the agent and the model call run decides what we can plug in. That is why headroom cannot help Devin.

Proxies (headroom, caveman proxy)

Need the agent to send model calls through localhost. Only Claude Code does; Devin calls its own gateway.

Hooks & plugins (cost-coach, rtk, TokenEconomizer)

Need the agent process on your Mac: Claude Code and Devin CLI. Devin cloud: best-effort plugin hooks only.

Text & MCP (rules, skills, codegraph)

Work everywhere, including Devin cloud, because they travel with the repo.

docs.devin.ai: cli hooks, product-guides/plugins, billing/usage · Claude Code on Amazon Bedrock docs.11
[구조 차이] Claude Code는 에이전트가 내 Mac에서 돌고, 모델 호출이 내 Mac을 거쳐 AWS로 나갑니다. 그래서 그 사이에 headroom 같은 프록시를 끼울 수 있습니다. Devin은 CLI든 클라우드든 모델 호출이 Cognition 게이트웨이를 통해 나가고, 클라우드 세션은 에이전트 자체가 Cognition VM에서 돕니다. 그래서 프록시를 끼울 자리가 없고, headroom은 Devin에 적용할 수 없습니다. 훅은 에이전트가 내 Mac에 있을 때만, 텍스트 규칙과 MCP는 저장소와 함께 따라가니 어디서나 됩니다.

Decision rule, fixed before the run

A tool saves money only if median billed cost is ≥ 10% below base, every rep beats base’s worst rep, and quality holds.

Why one run lies

Same arm re-run swings ±30% on short tasks. After rep 1, four tools looked like 11–28% savings; all vanished by rep 3.

Deep dive A · tools that change behaviour

The only measured savings came from tools that reduce what the agent does.

TokenEconomizer

② agent turn

Microsoft Research · 5.6K★ · Apache-2.0

How: learns repo facts, prunes unused tools, stops failure loops.

Result: −18.4 to −30.9% cache-aware cost, 579 tasks, Pass@1 up in 4 of 5 setups.

Limits: authors’ own paper; first ~5 tasks per repo cost more; Claude Code only, not Devin.

0 → −24%

Ponytail (as a rule)

⑤ output

188K★ · MIT · skill

How: “smallest change first”: reuse, no speculative code.

Result: −10.3% billed cost, p=0.004 (JetBrains, 80 tasks). Ours, n=1 per scenario: −6% long RCA, +6% / +29% short tasks.

Limits: skipped tests/docs more often (27 vs 17 misses); trojan clone on a marketplace. Use the rule in AGENTS.md.

0 → −10%

codegraph

③ tool calls

77K★ · MIT · MCP

How: pre-built symbol graph; one query instead of grep → read → read.

Result: −16.3% cost on 7 large repos; file reads −76%.

Limits: ours v2 +5 / +28 / +7% (agent preferred grep, 32 calls in 9 sessions); +23% time; telemetry on.

+28 → −16%
Ranges = billed cost, pessimistic → optimistic. arXiv 2610.22732; JetBrains AI blog; narration-studio #3032; codegraph #1393.15
[딥다이브 A] 실제 절감이 확인된 세 도구입니다. 공통점은 텍스트가 아니라 에이전트의 행동을 줄인다는 것입니다. TokenEconomizer는 실패 루프와 안 쓰는 도구를 정리하고, Ponytail은 코드를 덜 쓰게 하고, codegraph는 파일 탐색 횟수를 줄입니다. 각각 한계도 분명합니다. TokenEconomizer는 개발자 논문뿐이고 Devin에서는 못 쓰고, Ponytail은 테스트와 문서 누락이 늘었고, codegraph는 짧은 질문에서는 오히려 비쌉니다.

Deep dive B · tools that compress text

Latest versions, best-case scenarios: the most-starred compressors still did not lower the bill.

headroom

④ model + cache

79K★ · Apache-2.0 · proxy

How: rewrites requests to compress JSON, logs, code.

Result: v0.44 cache mode (now default) −1 to +2%; old token mode +61% (4 cache rebuilds).

Limits: sees API keys + prompts, keys in cleartext, telemetry on; not usable with Devin.

+61 → −1%

rtk

③ tool output

86K★ · Apache + BUSL · hook

How: rewrites shell commands and filters their output.

Result: ours v1.2.0 −5 to +9% while rewriting 46 of 81 commands; JetBrains +7.6%; Quesma ±5%, Pass@1 −1–2 pt.

Limits: lossy output → retries (piped grep 59 → 0 lines); Bash only, not Read/Grep.

+9 → −5%

caveman

⑤ output

119K★ · Apache-2.0 · skill

How: terse answer style; v4 adds a proxy and cloud router.

Result: ours v4.1.0 +46% / −1% / +63%: the agent re-fetched compressed text 11–14× per long session.

Limits: ⅔ of output is reasoning + code it cannot shorten; CLI telemetry on.

+63 → −1%

Conclusion · the usage patterns we should adopt

Six habits that cut the atoms of the bill. No install required.

REBUILDS

New task, new session

After a break longer than the cache lifetime (5 min), start fresh with a short summary.

REBUILDS

Keep the prefix stable

Don’t edit CLAUDE.md / AGENTS.md / MCP / model during a session.

CALLS

One message, full intent

No bare “ok”: put the next instruction, spec and done-criteria in the same message.

NEW CONTEXT

Read less, once

Point to files and line ranges; ask for an aggregation script instead of dumping logs.

OUTPUT

Smallest change first

Reuse before writing; still require tests for fixes and doc updates.

CALLS

Stop loops early

After 2 corrections or 3 failed tries, restate the requirement or restart.

The cheapest wins are things we stop doing. cost-coach reminds you at exactly these moments.
Each habit maps to one bill atom from slide 10. Ready-to-use rule block: skills/cost-discipline/SKILL.md.18
[결론과 지향 패턴] 결론은 도구보다 습관입니다. 여섯 가지 습관이 각각 청구액의 원자 하나씩을 줄입니다. 쉬고 나서 큰 세션을 이어가지 말고 새 세션으로, 세션 중에 설정 파일 바꾸지 않기, ok만 보내지 말고 다음 지시까지 한 번에, 필요한 파일만 읽게 하기, 가장 작은 변경부터, 그리고 루프는 일찍 끊기. 설치 없이 오늘부터 할 수 있고, cost-coach가 바로 이 순간들에 알려줍니다.

Why Devin saves less than Claude
